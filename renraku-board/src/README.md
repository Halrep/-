# 職員連絡ボード — GAS プロジェクト（`src/`）

Google スプレッドシートに紐づくコンテナバインド型の Apps Script プロジェクトです。

## ファイル

| ファイル | 役割 |
|---|---|
| `Code.gs` | バックエンド（シート操作・集計・確認記録・督促メール・セットアップ） |
| `Index.html` | ウェブアプリのUI（1画面SPA。CSS/JSインライン） |
| `appsscript.json` | マニフェスト（タイムゾーン・ウェブアプリ設定・OAuthスコープ） |

## セットアップ手順

### A. 手動で貼り付ける場合（clasp 不要）

1. 運用用の Google スプレッドシートを新規作成。
2. **拡張機能 → Apps Script** を開く。
3. `Code.gs` の中身を `コード.gs` に貼り付け。
4. **＋ → HTML** で `Index` を作成し、`Index.html` の中身を貼り付け（拡張子 `.html` は不要、ファイル名は `Index`）。
5. プロジェクトの設定で「`appsscript.json` マニフェストファイルを表示」をON→ 中身を貼り付け。
6. エディタ上部の関数を `setup` にして **実行**（初回は権限承認）。→ 4シートとサンプルが生成される。
7. `職員マスタ` シートに実際の職員（氏名・メール・分掌・表示順・在職=TRUE）を入力。
8. **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行: **アクセスしているユーザー**
   - アクセスできるユーザー: **組織内の全員**
9. エディタで `installTriggers` を1回 **実行** → 毎朝7:30の督促メールが有効化。
10. 発行URLを職員に共有（ブックマーク推奨）。

### B. clasp で既存プロジェクトへ push する場合（スクリプトIDを使う）

> **認証はお手元のPCで行う必要があります。** clasp はあなたのGoogleアカウントでの
> `clasp login`（ブラウザ認証）が前提です。スクリプトIDは「送り先」を指すだけで、
> 認証の代わりにはなりません。

**スクリプトIDの調べ方**：対象スプレッドシート → 拡張機能 → Apps Script →
プロジェクトの設定（⚙️）→「スクリプト ID」をコピー。
（URL `https://script.google.com/…/projects/★★★/edit` の `★★★` 部分でも可）

```bash
# 1. clasp を用意（初回のみ）
npm i -g @google/clasp
clasp login                      # ブラウザで自分のアカウントを承認

# 2. このリポジトリの src/ に移動し、送り先を設定
cd renraku-board/src
cp .clasp.json.example .clasp.json
#   .clasp.json を開き "scriptId" に控えたスクリプトIDを貼る

# 3. Apps Script API を有効化（未設定なら）
#   https://script.google.com/home/usersettings で「Google Apps Script API」をON

# 4. 送信（Code.gs / Index.html / appsscript.json のみ push される）
clasp push
```

その後、Apps Scriptエディタで `setup` を実行 →『職員マスタ』入力 → デプロイ →
`installTriggers` 実行、という **A の 6〜10 と同じ流れ**で運用開始できます。

#### 既存のスプレッドシート（旧・日付シートが入ったファイル）へ送るときの注意

- `setup()` は **不足しているシートを追加するだけ**で、既存の25枚の会議シートは
  消しません（`ensureSheet_` は既存シートに触れず、空のときだけヘッダーを入れる）。
- `clasp push` は **同名のスクリプトファイルを上書き**します。その既存プロジェクトに
  別のコードがある場合は、push 前に控えを取ってください（このプロジェクトは
  `Code.gs` / `Index.html` / `appsscript.json` の3つだけを送ります）。
- 旧・日付シートの中身を新しい `連絡事項` シートへ自動で取り込みたい場合は、
  移行スクリプト（会議ごとに1レコード化）を別途用意できます。

## 関数一覧

| 関数 | 実行タイミング | 役割 |
|---|---|---|
| `setup()` | 初回手動 | シート・ヘッダー生成（＋列の移行）。サンプル会議・連絡を投入 |
| `installTriggers()` | 初回手動 | 督促メール＋年度リセットのトリガー登録 |
| `doGet()` | 自動 | ウェブアプリ配信 |
| `getInitialData()` | UI | ボード初期表示＋本人の最終ログイン更新 |
| `registerMe(name, homeroom)` | UI | 初回アクセス時の自己登録 |
| `recordCheck(id, done, checkType)` | UI | 確認／対応の記録・取消（要対応は「確認した」「対応済み」の2段階） |
| `submitItem(payload)` | UI | 連絡の起票。追加した連絡（と新規会議）を返し、一覧を再読込せずその場に反映 |
| `editItem(id, payload)` | UI | 起票済みの議題・連絡の編集（発信者のみ。会議・種別は変更不可） |
| `getMeetingAgenda(id)` | UI | 会議アジェンダ取得（編集可否・コメント数・連絡の月番号付き） |
| `getCalendarEventsForMonth(ym)` | UI | 共有カレンダーの予定（ホバー表示用。未設定・失敗時は空） |
| `getUncheckedNames(id)` | UI | 未対応者名の取得 |
| `getComments(id)` / `addComment(id, text)` | UI | コメントの取得・投稿（全員可、編集・削除は無し） |
| `togglePin(id, pinned)` | UI | 自分のピン留めのON/OFF（個人ごとの目印。他の職員には見えない） |
| `sendReminders()` | トリガー | 期限超過の未対応者へメール（全連絡が対象） |
| `sendRemindersMine()` | UI | 「確認状況」タブの督促ボタンから手動送信。自分が発信した連絡のみが対象 |
| `yearEndReset()` | トリガー | 4/1のみ6シート（職員マスタ・連絡事項・確認ログ・会議・コメント・ピン）をアーカイブ＆リセット |

### 議題・連絡の編集（発信者のみ）

- ボードのカード、会議アジェンダ表の各行に✏️編集ボタンが出る（自分が発信者のときのみ）。
- 会議への紐づけと種別（協議／連絡）は編集できない。変更したい場合は起票し直す。
- 作成者メールが記録されていない旧データ（このバージョンより前に追加されたもの）は
  誰でも編集できる。最初の編集で編集した人が作成者として記録される。

### コメント

- 全職員が議題・連絡に自由にコメントできる、投稿のみのシンプルな仕組み（編集・削除は無し）。
- カード側は件数バッジのみを軽量に表示し、モーダルを開いたときに内容を取得する。

### 重要な連絡

- 起票フォームの「⚠️ 重要」にチェックを入れると、カードが**赤く強調**され（左に太い赤帯＋淡い赤の下地）、
  「⚠️ 重要」チップが付く。並び順も月セクションの先頭に来る。
- ピン留めが**個人の目印**（自分にしか見えない）なのに対し、重要は**発信者が全員に向けて示す印**。
  役割が違うので併用できる。
- 後から編集で切り替えられる（ボードのカード・会議アジェンダ表のどちらからでも）。

### ピン留め（個人ごとの目印）

- カードの★ボタンで自分だけの目印を付けられる。**他の職員からは見えず**、進捗の集計にも関与しない。
- 「自分の未対応」が拾えない連絡（閲覧のみ・自分が対象外・対応済み・期限なし）を
  手元に残しておくための仕組み。
- 留めた連絡は**サイドバー最上部に常時表示**（絞り込みの状態に関係なく全件）。
  ピンが0件のときはパネルごと隠れる。
- 本体のカードでじっくり見たいときは、絞り込みバーの「★ピン留めのみ」を押す。
  ピンは完了済みの連絡にも付けられるので、ONにすると対応状況を自動的に「すべて」へ広げる。

### 画面構成（3タブ）

「連絡ボード」「会議」「確認状況」の3つ。連絡は1つのタブに集約し、表示範囲は
**対応状況フィルタ**（未完了のみ／すべて／完了のみ、既定は未完了のみ）で切り替える。

- 旧構成では「今日のボード／完了した連絡」を*対象者全員が対応したか*で分けていたため、
  ある連絡がどちらにあるかを本人が予測できず、探すとき2タブを行き来していた。統合により
  「すべて」に切り替えれば1箇所で全件から検索できる。
- 「自分が済ませた連絡」の折りたたみは **`filterStatus==='undone'` のときだけ**働く
  （完了を含む表示で畳むと、ほぼ全件が隠れて空に見えるため。`renderList` を参照）。
  リスト全体で1つの折りたたみにまとまり、開閉状態は `foldDoneOpen` が持つ。
- 「自分の未対応」タブは右サイドバーへ移したため廃止。
- 「確認状況」は `isMine`（自分が発信したか）で絞る。`isMine` は作成者メールの一致で判定し、
  作成者メールが無い旧データは発言者名と自分の氏名の一致で代用する。

### 一覧の並びと通し番号

- 「連絡ボード」は**1本の連続したリスト**（`renderList`）。並び順は
  月が新しい順 → その月の中を 重要 → 要対応 → 期限が近い順。
- 月の絞り込みはプルダウンで行う。以前は「月ごとの開閉セクション」もあったが、
  プルダウンと役割が重複していたうえ、月ヘッダーと「要対応／閲覧のみ」の見出しで
  **1か月あたり約180px**を消費し、ノートPCではカードが1〜2枚しか見えなかったため廃止した。
  「要対応／閲覧のみ」はカードのチップと並び順で分かるので、見出しも併せて廃止。
- 画面上部の概況（掲載中／期限が今日・超過／あなたの未対応）は、カード3枚から
  **1行のテキスト**に変更（約78px → 約28px）。
- 連絡事項（協議事項は対象外）には `buildMonthNoMap_()` が**月ごとに1からリセットされる
  通し番号**を振る。シートの行順＝追加順として扱うため、行を並べ替えない限り安定する。
  カードのバッジ、会議アジェンダの「連絡事項」表の No. 列、どちらにも同じ番号が出るので、
  打ち合わせで「5番を見てください」と言えば board 上のどのカードか一意に伝わる。
- 番号が月ごとに戻る以上、月をまたいで並べると「何月の5番か」が分からなくなる。
  そのため**表示中の連絡が2か月以上にまたがるときだけ**、細い月の区切り
  （`.month-divider`。罫線＋ラベルのみで開閉ボタンは無い）を挟む。1か月しか
  出ていないときは曖昧さが無いので区切りも出さない。

### サイドバー（ミニカレンダー＋自分の未対応）

画面右に常時表示。カレンダーの日付をクリックすると、その日に追加された連絡と
その日が期限の連絡へジャンプする（絞り込みを解除し、必要なら「自分の済み」の
折りたたみを開いてスクロール＋ハイライト）。
下部には自分が対象で未対応の連絡が期限の近い順に並ぶ。

**共有カレンダーの予定をホバー表示する（任意）**

日付にカーソルを乗せたときに学校の予定を出したい場合のみ設定する。

1. 表示したい Google カレンダーを開き、**設定と共有 → カレンダーの統合**の
   「カレンダー ID」をコピー（例 `abc123@group.calendar.google.com`）。
2. そのカレンダーを、アプリを使う職員が**閲覧できる状態**にしておく
   （「特定のユーザーと共有」または学校ドメイン全体に公開）。
3. `Code.gs` 冒頭の `SHARED_CALENDAR_ID` にそのIDを貼る。
4. `clasp push` 後、Apps Script エディタで任意の関数を1回実行して
   **カレンダー閲覧の権限を承認**する（`appsscript.json` に
   `calendar.readonly` を追加済み）。デプロイ済みの場合は
   「デプロイを管理 → 新バージョン」で反映する。

未設定のままでも他の機能に影響はない（ツールチップが出ないだけ）。
ID誤りや権限不足で読めない場合も同様に、静かに無効化される。

### 職員名簿の維持（担当者に依存しない）

- **初回アクセス時に自己登録**：職員が初めて開くと名前を一度入力するだけで名簿に加わる（`setup()` は職員を初期投入しない）。
- **1ヶ月ログインの無い職員は自動で対象外**：`最終ログイン` が `INACTIVE_DAYS`（既定30日）より前だと集計から除外。日数は `Code.gs` 冒頭で変更可。
- **年度末リセット（アーカイブ）**：`installTriggers()` が毎朝3:30に日付を確認し、4/1のみ `職員マスタ`・`連絡事項`・`確認ログ`・`会議` の4シートを `シート名_YYYY年度` に退避して空にする。実行日は `RESET_MONTH` / `RESET_DAY` で変更可。
  - 稼働データを常に1年度分に保つため、データが何年分たまっても読み込みが遅くならない。
  - 過去データはアーカイブシートに残る。同名アーカイブが既にあれば退避はスキップ（二重実行しても安全）。
  - 年度をまたぐ連絡（3月起票・4月期限など）は、新年度に起票し直す運用とする。

### すでに `setup()` を実行済みで、このバージョンに更新する場合

1. `clasp push` で再送信。
2. Apps Scriptエディタで **`setup` をもう一度実行**（`職員マスタ` に `最終ログイン` 列、
   `連絡事項` に `作成者メール`・`重要` 列を自動追加。**`コメント` と `ピン` のシートを新規作成**するため、
   このバージョンでは必ず実行すること — 実行しないと `getInitialData` が
   「シートが見つかりません」で失敗し、ボードが開けなくなる）。既存データは消えない。
3. サンプルで入っていたダミー職員（西村・横田・清水）が残っていれば、その行を削除。以降は自己登録で埋まる。
4. **`installTriggers` を実行**（年度リセットのトリガーを追加）。

## 補足・カスタマイズ

- **督促の時刻**: `installTriggers()` の `atHour(7).nearMinute(30)` を変更。
- **督促の条件**: `sendReminders()` は「掲載中・要対応・期限が当日以前・未対応」の職員を対象。期限前日から送りたい等は同関数の日付判定を調整。
- **担任の判定**: `職員マスタ` の `分掌` に「担任」を含む職員を対象区分「担任」の対象とみなす。
- **OAuthスコープ**: `spreadsheets.currentonly` はこのスプレッドシートのみアクセス可能な最小権限。他ファイルを参照する拡張時は広げる。
- **他の職員の更新**: GASにはプッシュ通知が無いため、`Index.html` が60秒ごとに
  `getInitialData()` を呼ぶ自動ポーリングと、ヘッダーの「⟳ 更新」ボタン（手動）で
  新着を取り込む。間隔は `POLL_INTERVAL_MS` で変更可。31名規模での60秒間隔は
  GASの実行回数クォータに対して十分余裕がある。
- **既存データの移行**: 旧・日付シート群から `連絡事項` シートへ移す移行スクリプトは別途用意可能（会議ごとに1レコード化）。
