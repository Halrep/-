# SRLアプリ — GASプロジェクト

Google スプレッドシートをデータベース、Google Apps Script をウェブアプリとして動かす、
自己調整学習（SRL）支援アプリの実装です。1クラス＝1スプレッドシートを基本単位とします。

## 設計の中心：単元内自由進度学習

**公開の単位は「本時（1時間）」ではなく「単元」です。**
子どもは単元の課題プールから、**自分のペース・自分の順序**で課題を選んで進みます。
同じ時間に、子どもによって違う課題にいるのが前提です。

- **課題（学習カード）** は種別を持ちます：`必須`（かならずやること）／`選択`（えらべる活動）／`発展`（やりきったら挑戦）
- 課題は **段階的に公開** できます（環境は変えないと風景になる ── 最初に全部を見せず、動きが鈍ったら投入する）
- **資料と推奨方略は課題ごと** に紐づきます（`task_id` が空なら単元共通＝いつでも使える資料）
- 進度・取り組み方の選択・方略利用・**分かりぐあい・メモ**は **課題ごと**、計画・確認タイム・振り返りは **日ごと** に記録します

### 学びの足跡

記録は貯めるだけでなく、子ども自身に返します（ふりかえるタブ「学びの足跡」）。

- **課題ごとの足跡**：進んだ跡・分かりぐあい・メモ・使った工夫を、単元ごとにまとめて表示
- **日ごとのきろく**：その日立てた計画と振り返りを組にして、新しい順に表示
- **うつりかわり**：自己効力感（やれそう）と達成度が日を追ってどう動いたか
- **単元をまたいで残る**：終わった単元の足跡も消えません（次の単元が始まっても参照できる）

**分かりぐあい**（`まだわからない` / `すこしわかった` / `だいたいわかった` / `人に説明できる`）は
評価ではなく自己申告です。自分の弱点をつかむための目盛りとして扱い、押し直せば未選択に戻せます。
**メモ**は振り返りではなく、取り組みながら書く「気づき・大切だと思ったこと・分からなかったこと」です。

教師側では、**「できた」なのに分かりぐあいが低い課題**を児童詳細に出します。
これは子どもの落ち度ではなく、手引きや資料が足りていない環境のサインとして読みます。

## できること

- **初期セットアップ**：シート17枚の自動生成＋方略・選択肢のサンプルマスタ、6年社会のデモ単元（課題9件）を投入
- **児童アプリ（3タブ）**：みとおす（単元の出口・学習の手引き・きょうの計画Be/Do/Regulate・自己効力感）→ やってみる（課題を選ぶ → その課題の取り組み方・資料・工夫／**分かりぐあい・課題メモ**／確認タイム／こまったボタン／みんなの様子）→ ふりかえる（計画とのズレ・達成度・原因帰属・気持ち・次への適用・教材リクエスト・**学びの足跡**）
- **教師アプリ（3タブ）**：授業モニタ（**環境の診断**・**いま誰がどの課題にいるか**の分布・I/You/We・タイル・詳細＋**見取りメモ**＋フィードバック、15秒ポーリング）／単元デザイン（手引き・課題の段階的公開・選択肢の開放・他者参照の可否）／ふりかえり一覧（日付切替・未記入把握・共有・単元の改善リスト）

## ファイル構成（clasp でフラット管理）

| ファイル | 役割 |

| `appsscript.json` | マニフェスト（Asia/Tokyo・ドメイン内アクセス・自分として実行） |

| `Code.gs` | doGet（ロール出し分け）・onOpenメニュー・共通ヘルパー |
| `Setup.gs` | 初期セットアップ・サンプル投入・記録消去 |
| `StudentApi.gs` | 児童向けサーバー関数 |
| `TeacherApi.gs` | 教師向けサーバー関数 |
| `css.html` / `js_common.html` | 共通スタイル・共通JS（run ラッパ／トースト） |
| `student.html` / `teacher.html` / `unauthorized.html` | 各画面 |

## セットアップ手順

### A. clasp を使う場合（推奨・版管理できる）

```bash
npm install -g @google/clasp
clasp login
# スプレッドシートに紐づくコンテナバインド型スクリプトを作成
clasp create --type sheets --title "SRLアプリ" --rootDir ./src
# .clasp.json が生成される（scriptId はコミットしない）
clasp push
```

### B. 手動で貼り付ける場合

1. スプレッドシートを新規作成 → 拡張機能 ▸ Apps Script
2. `.gs` の中身を同名ファイルとして作成し貼り付け
3. `.html` はファイル種別「HTML」で同名（拡張子なし）で作成し貼り付け
4. マニフェスト（`appsscript.json`）はプロジェクト設定で「マニフェストを表示」にして反映

## 使い始め（教師）

1. スプレッドシートを再読み込み → メニュー **「自己調整学習アプリ ▸ 初期セットアップ」** を実行
2. **名簿** シートに教師・児童を登録（`役割` 列は `teacher` / `student`、`email` は学校アカウント）
3. **デプロイ ▸ 新しいデプロイ ▸ ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**組織内の全員**
4. 発行URLを配布（児童は自分のアカウントで開くと児童画面、教師は教師画面が出る）
5. 「単元デザイン」タブで内容を整え **「この単元を公開」**（またはメニューの「デモ単元を公開中にする」）

## 結合テスト（ローカル）

GASのグローバル（SpreadsheetApp / LockService / Session / Utilities …）をインメモリで模した
ハーネスで、実際の `.gs` を読み込み「セットアップ→児童の操作→教師モニタ→フィードバック→振り返り」を
通しで検証できます（Googleへのデプロイ不要）。

```bash
node tests/harness.test.js
```

セットアップ・ロール判定・**自分のペース/順序での進行**・課題ごとの取り組み方と履歴・
**同時に違う課題にいる状態**・課題分布・段階的公開・他者参照・確認タイム・振り返り（計画とのズレ／教材リクエスト）
**課題ごとの分かりぐあい・メモ**・**単元をまたぐ学びの足跡**
まで、104項目を確認します。

## 開発時のテスト（なりすまし）

エディタから動作確認するときは、スクリプトプロパティ `DEV_IMPERSONATE_EMAIL` に
名簿上のメールを設定すると、そのユーザーとしてログインした扱いになります（本番では削除）。

## 研修「単元内自由進度学習」からの設計方針

- **教師は待つ**：モニタは介入を急かす警告ではなく、**環境の診断**（手引き・資料・課題の粒度が足りているか）として表示する
- **見取りは仮説で行う**：見取りメモは事実と解釈（仮説）を分けて記録し、あとで同僚と語り合えるようにする
- **振り返りは反省をしない**：「計画とのズレ」を見て、「こんな教材があれば分かった」を集め、次年度の改善に使う
- **環境は変えないと風景になる**：課題・資料は段階的に公開できる

## いまの割り切り（今後の拡張候補）

- AIによる方略提案・振り返りの傾向分析は未実装
- 課題・資料の新規追加はスプレッドシート直接編集（アプリからは公開/紐づけのトグルのみ）
- 2教科同時進行（公開できる単元は1件）は未対応
- モニタは全件ポーリング（差分取得・夜間集計バッチは今後）
- **成果物の写真が残せない**：足跡は文字だけで、ノートや作品そのものは記録できない。
  カメラ撮影とDrive保存を入れるには `appsscript.json` に Drive 権限（`drive.file`）を足す必要があり、
  児童全員の同意画面が変わるため、導入は学校側の判断が要る
