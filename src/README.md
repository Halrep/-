# SRLアプリ — GASプロジェクト

Google スプレッドシートをデータベース、Google Apps Script をウェブアプリとして動かす、
自己調整学習（SRL）支援アプリの実装です。1クラス＝1スプレッドシートを基本単位とします。

## 設計の中心：単元内自由進度学習

**公開の単位は「本時（1時間）」ではなく「単元」です。**
子どもは単元の課題プールから、**自分のペース・自分の順序**で課題を選んで進みます。
同じ時間に、子どもによって違う課題にいるのが前提です。

- **課題（学習カード）** は種別を持ちます：`必須`（かならずやること）／`選択`（えらべる活動）／`発展`（やりきったら挑戦）／`ゴール`（成果物そのものをつくる課題）
- **`ゴール` は単元にひとつだけ**です。成果物イメージ（例：大名支配のしくみ新聞）を掲げても、
  それを作る課題が「発展＝やりたい人だけ」のままでは、ゴールに着かないまま単元が終わります。
  ゴール課題はどの子の道すじにも必ず入り、**いつも道すじのいちばん最後**にすわります
  （別の課題をゴールに指定すると、前のゴールは自動で `必須` に戻ります）
- 課題は **段階的に公開** できます（環境は変えないと風景になる ── 最初に全部を見せず、動きが鈍ったら投入する）
- **資料と推奨方略は課題ごと** に紐づきます（`task_id` が空なら単元共通＝いつでも使える資料）
- 進度・取り組み方の選択・方略利用・**分かりぐあい・メモ**は **課題ごと**、計画・確認タイム・振り返りは **日ごと** に記録します

### ゴールまでの道すじ（単元の計画）

「みとおす」の1画面目は、読むための手引きではなく **自分で組み立てる道すじ** です。
課題を飛び石（ノード）、あいだの線をつながり（コネクタ）として並べ、🚩スタートから🏁ゴールまでの
順序を子ども自身が決めます。**単元をとおした計画**なので、日をまたいでも残り、あとから何度でも変えられます。

道すじは**ゴールをはさんで2つの区間**に分かれます。行き先は課題の種別で決まります。

```
🚩スタート →［必須・えらべる活動］→［ゴール課題］→ 🏁ゴール →［発展］
```

`発展` は「やりきったら挑戦」なので **ゴールのむこう** にだけ置けます。ゴールの手前には入りません
（先にやることではないため）。逆に `必須` と `選択` はゴールより後ろへは行けません。

- **タイルをつまんで動かす**と、両どなりのつながりがいったん**はずれ**、残ったどうしが**結び直り**ます
- 置きたいところに近づけると、そのつながりが**割れて受け口ができ**、指をはなすと**吸いつき**ます
- **道すじから外す**のは「そえる課題」の置き場に戻したときだけ。どこでもない所で落としても何も起きません
- `必須` と `ゴール` は外せません（順番は自由。ゴールだけはゴール旗の直前に固定）
- **動かせるのは自分の区間の中だけ**。◀▶ も、つまんで運ぶときの受け口も、入れる区間にしか出ません
- ドラッグが使えない環境でも同じことができるよう、**◀ ▶ と ＋ 道すじに入れる／外す のボタン**も置いています
- 「やってみる」の課題一覧も**自分の道すじの順**にならび、上に小さい道すじが出ます

道すじは `学習計画` シートに **1人1単元1件** で持ちます（順序そのものが計画なので、履歴ではなく最新を上書き）。
サーバー側で毎回ならし直すので、先生が課題を消した・非公開にした・あとから必須を足した場合も壊れません。

### 学びの足跡

記録は貯めるだけでなく、子ども自身に返します（ふりかえるタブ「学びの足跡」）。

- **課題ごとの足跡**：進んだ跡・分かりぐあい・メモ・使った工夫を、単元ごとにまとめて表示
- **日ごとのきろく**：その日立てた計画と振り返りを組にして、新しい順に表示
- **うつりかわり**：自己効力感（やれそう）と達成度が日を追ってどう動いたか
- **単元をまたいで残る**：終わった単元の足跡も消えません（次の単元が始まっても参照できる）

**学びログ（写真）** も足跡の一部です。文字だけではノートも作品も残らないので、
課題ごとにカメラで撮って残せます。撮った写真は「みんなの学びログ」で見合うこともできます。

**分かりぐあい**（`まだわからない` / `すこしわかった` / `だいたいわかった` / `人に説明できる`）は
評価ではなく自己申告です。自分の弱点をつかむための目盛りとして扱い、押し直せば未選択に戻せます。
**メモ**は振り返りではなく、取り組みながら書く「気づき・大切だと思ったこと・分からなかったこと」です。

教師側では、**「できた」なのに分かりぐあいが低い課題**を児童詳細に出します。
これは子どもの落ち度ではなく、手引きや資料が足りていない環境のサインとして読みます。

### 学びログ（カメラ・ビュー）の置き場と見える範囲

写真の実体は **Drive**、シート（`学びログ`）には **ファイルIDだけ** を持ちます。

- 保存先は `SRLアプリ_学びのきろく / 教科_単元名 / 日付 /`。
  ファイル名は `生徒ID_氏名_撮影年月日_時刻.jpg`
- ウェブアプリは「**自分（＝デプロイした教師）として実行**」なので、
  DriveApp は常に教師のドライブを見ます。**子どものアカウントに Drive の権限は要らず、
  同意画面も変わりません**。写真が子どものドライブに入ることもありません
- スコープは `drive.file`（アプリが作ったファイルだけ）。教師の既存ファイルには触れません。
  この制約のためスプレッドシートの親フォルダは辿れず、置き場はドライブ直下に作って
  フォルダIDをスクリプトプロパティ `LOG_ROOT_FOLDER_ID` に覚えます
- 画像は一覧では返さず、**表示するぶんだけ1枚ずつ**取りに行きます（30人分をまとめて返すと詰まるため）

見える範囲は三重に絞っています。

1. 自分の写真はいつでも見られる
2. ほかの子の写真は、**教師が「他者参照」を開いていて**、かつ **本人が共有をオンにしている** ものだけ
3. 匿名モードでは撮影者名を伏せる（他者参照の設定に合わせる）

取り消しは本人だけができ、**Drive の実体もゴミ箱に入ります**。
シートの行だけ消すと写真がドライブに残り続けるため、メニューの「記録を消去」は
`学びログ` に触れません（写真は1枚ずつ取り消す運用）。

> **カメラの動作について**：まず `getUserMedia` でその場のカメラを開こうとしますが、
> Apps Script のウェブアプリはサンドボックス iframe で動くため、環境によっては
> カメラを直接開けません。その場合は自動で「写真をえらぶ」（`<input type="file" capture>`）に
> 切り替わり、端末のカメラアプリで撮って選ぶ流れになります。どちらでも保存先は同じです。

## できること

- **初期セットアップ**：シート19枚の自動生成＋プルダウン設定＋方略・選択肢のサンプルマスタ、6年社会のデモ単元（課題9件）を投入
- **児童アプリ（3タブ・1画面1まとまり）**：みとおす（① 単元の出口と**ゴールまでの道すじづくり** → ② きょうの計画）／やってみる（課題をえらぶ → その課題だけの画面を **はじめる・すすめる・おわりに** の3帯で）／ふりかえる（① 計画とのズレ → ② そのわけと気持ち → ③ 次にいかす）。**🆘こまった と みんなの様子は右カラムに常設**、資料・学びログ・**学びの足跡**はヘッダーや脇のボタンから引き出しで開く
- **教師アプリ（3タブ）**：授業モニタ（**環境の診断**・**いま誰がどの課題にいるか**の分布・I/You/We・タイル・詳細＋**見取りメモ**＋**学びログの写真**＋フィードバック、15秒ポーリング）／単元デザイン（**単元・課題・資料の登録と編集**・手引き・課題の段階的公開・選択肢の開放・他者参照の可否）／ふりかえり一覧（日付切替・未記入把握・共有・単元の改善リスト）

## セットアップ手順

### A. clasp を使う場合（推奨・版管理できる）

```bash
npm install -g @google/clasp
clasp login
# スプレッドシートに紐づくコンテナバインド型スクリプトを作成
clasp create --type sheets --title "SRLアプリ" --rootDir ./src
# .clasp.json が生成される（scriptId はコミットしない）
clasp push
```

### B. 手動で貼り付ける場合

1. スプレッドシートを新規作成 → 拡張機能 ▸ Apps Script
2. `.gs` の中身を同名ファイルとして作成し貼り付け
3. `.html` はファイル種別「HTML」で同名（拡張子なし）で作成し貼り付け
4. マニフェスト（`appsscript.json`）はプロジェクト設定で「マニフェストを表示」にして反映

## 使い始め（教師）

1. スプレッドシートを再読み込み → メニュー **「自己調整学習アプリ ▸ 初期セットアップ」** を実行
2. **名簿** シートに教師・児童を登録（`役割` 列は `teacher` / `student`、`email` は学校アカウント）
3. **デプロイ ▸ 新しいデプロイ ▸ ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**組織内の全員**
   - 学びログ（写真）のために Drive の権限を求められます。**承認するのは教師だけ**で、
     子どもの同意画面は変わりません。既存のデプロイを更新した場合は、
     一度アプリを開いて再承認しないと写真の保存が失敗します
4. 発行URLを配布（児童は自分のアカウントで開くと児童画面、教師は教師画面が出る）
5. 「単元デザイン」タブで内容を整え **「この単元を公開」**（またはメニューの「デモ単元を公開中にする」）

## 結合テスト（ローカル）

```bash
node tests/harness.test.js
```

**課題ごとの分かりぐあい・メモ**・**単元をまたぐ学びの足跡**・
**学びログの保存と見える範囲**（Drive はインメモリのモックで代用）・

まで、267項目を確認します。

## 児童画面の組み立て（1画面1まとまり）

情報量が多いと「どこを見ればよいか」が分からなくなるので、
**大きなまとまりごとに1画面**にし、進んだことが分かるようにしています。

| タブ | 画面 |
|---|---|
| ① みとおす | `1/2 この単元でやること`（出口・**ゴールまでの道すじづくり**）→ `2/2 きょうの計画`（Be/Do/Regulate/できそう度） |
| ② やってみる | **道すじを歩く**（みとおすと同じ地図。飛び石をタップ）⇄ **その課題だけの画面** |
| ③ ふりかえる | `1/3 計画とのズレ` → `2/3 そのわけと気持ち` → `3/3 次にいかす` |

**②だけは1本道にしていません。** 自由進度学習では、子どもは課題を自分の順序で選び、
資料に戻ったりを繰り返します。ここをウィザードにすると設計思想と噛み合いません。
代わりに「地図 ⇄ 1課題」の2層にして、1画面に出る量を減らしています。

### 組むところと歩くところは、同じ地図

②の一覧は、①で組んだ道すじ**そのもの**です。組むときと歩くときで見た目が変わると、
同じ計画だと分からなくなるためです。

- **飛び石をタップ**すると、その課題の画面に入ります
- 「✔できた！」を押すと**道すじに戻ります**。石が埋まり、ゴールの「あと◯こ」が減ります
- **つぎに立つ飛び石**（取組中、なければ未着手の先頭）に印が付きます
- ②では**並べ替えません**。作業中にうっかり計画が変わっては困るためです。
  組みかえたくなったら **🧭 道すじを組みかえる** で①に戻ります ── それ自体が「調整する」という行為です

飛び石は**同じ幅のマスに並べます**（CSS グリッド）。幅ぴったりに詰めると行ごとに切れる位置がずれ、
散らかって見えるためです。スタートとゴールの目印も同じ1マスを使います。

課題の中は3つの帯に分けます。**見通す→実行→振り返るを課題1つの中で回す形**で、
画面整理と学習モデルを一致させています。帯は自由に行き来できます。

| 帯 | 中身 |
|---|---|
| 🚩 はじめる | 課題の説明・取り組み方をえらぶ → ▶取りかかる |
| ✏️ すすめる | この課題でつかう資料・工夫 |
| 🏁 おわりに | 分かりぐあい・メモ・学びログ → ✔できた！ |

### 読める・押せる・書ける（低学力の児童とアクセシビリティ）

対象は小学校高学年で、読み書きに困難のある児童も使います。
実際に描画して測ったうえで、次を満たしています（明るいテーマ・暗いテーマの両方、全タブ）。

| | 基準 | いま |
|---|---|---|
| 文字と背景のコントラスト | 4.5:1（WCAG AA） | 不足 **0件** |
| 文字の大きさ | 12.5px 以上 | 12.5px 未満 **0件** |
| 押せる大きさ | 44×44 | 44px 未満 **0件** |

- **塗り用の色と文字用の色を分けています**（`--ok` と `--ok-ink`）。
  塗りとして選んだ色を小さな文字に使うと、いちばん読ませたい合図（できた／つぎはここ／
  こまっています）がいちばん薄くなります
- 塗りつぶしバッジの文字色は `--on-fill`。暗いテーマの ink は明るい色なので、白のままでは読めません
- **ふりがな**を切り替えられます。自動生成は読みを取りちがえる（まちがったふりがなは無いより悪い）ので、
  **読みが一つに定まる語だけの辞書**を持ち、その語にだけ振ります。辞書に無い語には何も振りません
- **文字の大きさ**を 標準／大／特大 で切り替えられます。つまんで動かす操作も拡大した座標のまま動きます
- **自由記述には「ことばをえらぶ」ボタン**を添えています。白紙の欄だけ置くのは、書ける子にだけ
  開かれた設計です。押すと文が入り、あとから直せます。きょうの計画の候補は**その子の道すじ**から作ります
- **声で入れる**ボタン（Web Speech API）。サンドボックス iframe でマイクを開けない環境があるので、
  一度断られたらそのあとは出しません（押しても使えないボタンが並ぶほうが困るため）
- 道すじは `role="list"` と `aria-posinset` で**順番のあるもの**として読み上げられ、
  いま立つ石には `aria-current="step"` が付きます。線や旗は飾りなので読み上げから外しています
- 児童の画面では**教師の言葉を使いません**（単元→この学習、必須→かならず、方略→工夫、
  Be/Do/Regulate→①②③の日本語）。教師の画面はこれまでどおりの語です

> 実機と実際のスクリーンリーダーでの確認はまだです。漢字も学年別漢字配当表との機械照合ではなく、
> 児童に見える文字列を抜き出して目で確かめたものです。

### 常に手が届くところに置くもの

**🆘こまった** と **みんなの様子** は右カラムに常設します（下に並べると埋もれるため）。
画面が狭いとき（900px以下）は1カラムになり、**こまったボタンだけ画面の下に貼り付けます**。

**資料・みんなの学びログ・学びの足跡**は「参考にしたい時に開く」ものなので、
常設せず引き出し（右からのシート）で開きます。足跡はヘッダーの 👣 からいつでも見られます。

### 教師が、その子の道すじを見る

授業モニタで児童を選ぶと、**その子が組んだ道すじ**が出ます（児童画面と同じ並び・同じならし方）。

- 何を先にやると決めたか、いまどの石で止まっているか
- **道すじに入れていない課題**（選ばなかったもの）も並べます
- **最後に組み直した時刻**も出します。計画をいつ変えたかは見取りの手がかりになります

進み具合だけを並べても「その子がどう計画したか」は見えないので、順序ごと出しています。

### 教師画面からシートを開く

ヘッダーの **📊 シートを開く** から、スプレッドシート本体と、よく使うシート
（名簿・単元・課題・資料・学びログ）へ直接飛べます。公開中の単元に単元シートがあれば、
それも先頭に出ます。記録の細かい確認や一括の貼り付けは、シートのほうが早いためです。

### 進んだことが分かる仕掛け

- 画面上部に**必須メーター**（`1 / 5`＝必須＋ゴール課題）。「できた！」を押すとバーが伸びます
- ステップの現在地を丸で示し、いまいる所が**脈打ちます**。済んだ所は ✓ になります
- 画面の切り替えは**進む＝右から入る／戻る＝左から**。向きで迷子になりにくくします
- 「できた！」と「ふりかえりを記録」は、押した場所から**小さく弾ける演出**が出ます
- `prefers-reduced-motion` が有効な端末では、動きをすべて止めます

## 単元・課題・資料の編集

「単元デザイン」タブから、スプレッドシートを開かずに次ができます。

| できること | 置き場所 |
|---|---|
| 単元をつくる／消す | ヘッダーの **＋ 単元をつくる** / **単元を消す** |
| 単元の手引きを直す | 各入力欄（自動保存） |
| 課題を追加・編集・並べ替え・削除 | 課題カードの **＋ 課題を追加** と各行の ↑ ↓ ✎ 🗑 |
| 資料を追加・編集・隠す・削除 | 課題の資料チップをクリック、または **＋ 資料** |

設計上の決め事が3つあります。

- **追加した課題は非公開で入ります。** 「環境は変えないと風景になる」ので、
  出すタイミングは教師がスイッチで決めます
- **子どもの記録がぶら下がっているものは消せません。** 記録は `task_id` / `unit_id` の
  文字列を持っているだけなので、元を消すと記録が迷子になります。
  課題は「公開」を切る、単元は「終了」にする——どちらも足跡は残ります
- **資料のURLは `http(s)` だけ通します。** 子どもの画面にリンクとして出るためです

## 単元シート（1単元＝1枚で書く）

単元／課題／資料の3シートを行き来しながら `unit_id` を貼って回るのは煩雑なので、
**1単元＝1枚の編集シート**を用意しました。まとまった量を書くときはこちらが速いです。

| メニュー | すること |
|---|---|
| 単元シートを新しく作る | 単元名を聞いて `単元_〇〇` シートをひな形付きで作る |
| この単元シートを取り込む | 開いているシートを読んで、単元・課題・資料に反映 |
| 既存の単元を単元シートに書き出す | いまある単元を1枚に展開して、あとから直せるようにする |

1枚の中は3つに分かれています。

```
A1  単元シート │ (unit_id は自動)
    教科 / 学年 / 単元名 / 単元の問い・目標 / 単元の出口 / 総時数 / 確認タイム間隔 / 裁量レベル

■ 課題   種別 │ タイトル │ 説明 │ めやす分 │ 公開 │ task_id（自動）
■ 資料   課題番号 │ アイコン │ タイトル │ 補足 │ 種別 │ URL │ 公開 │ resource_id（自動）
```

- **課題の並びは行順**です。行を入れ替えれば順番が変わります
- **資料の「課題番号」は上の課題の並び（1、2、3…）**。`task_id` を貼る必要はありません。
  空にすれば「いつでも使える資料」になります
- **取り込みは何度でもやり直せます。** 取り込むと `task_id` / `resource_id` が
  シートに書き戻され、次からは追加ではなく更新になります。**この列は消さないでください**
- シートから消した行は取り込み時に削除されますが、**子どもの記録がある課題は残します**
  （残したもの・読めなかった行は取り込み後のダイアログで知らせます）

正本はこれまでどおり `単元` / `課題` / `資料` シートです。単元シートは書くための作業面で、
細かい直しはアプリの「単元デザイン」タブのほうが速いこともあります。使い分けてください。

## 打ち間違いを防ぐプルダウン

決まった選択肢の列は、初期セットアップ時にプルダウンになります
（`名簿` の役割、`単元` の学年・状態・裁量レベル・他者参照、`課題` の種別・公開、
`資料` の種別・公開、`方略マスタ` の分類・推奨フェーズ、`選択肢マスタ` のカテゴリ など）。
単元シートの種別・公開・学年も同様です。

`名簿` の `役割` を打ち間違えるとログインできなくなるなど、静かに壊れる箇所を減らすためです。
「その他の値も許す」設定にしてあるので、既に入っている値が消えることはありません
（外れた値には警告の三角が出ます）。

**すでにセットアップ済みのシートにプルダウンを付けるには、
メニューの「初期セットアップ」をもう一度実行してください。** 既存のデータは消えません。

## 表示の速さについて

GAS は往復ごとにシートを丸ごと読むので、**1リクエストで何枚読むか**がそのまま待ち時間になります。

- **単元の読み込み（`teacher_getDesign`）は 19枚 → 7枚**。
  うち10枚は「この単元を消せるか」を数えるためだけだったので、
  **「単元を消す」を押したときだけ**調べる（`teacher_getUnitDeletable`）ように分けました
- **`Repo` に実行1回ぶんの読み取りキャッシュ**を入れました。
  同じシートを何度も読み直さなくなります（単元シートの取り込みは課題1件ごとに
  全件を読み直していました）。書き込んだシートはその場で捨てるので、
  同じ実行の中でも最新が返ります

> `Repo` を通さずシートを直接書き換えたときは、`Repo.dropCache()` を呼んでください
> （`setupClearRecords` はそうしています）。返る行オブジェクトはキャッシュと共有されるので、
> 呼び出し側で書き換えないでください。

## 反映のタイムラグについて

遅く感じる原因は2つあり、どちらも減らしました。

- **保存のたびに全体を取り直していた**：GAS は往復ごとにシートを丸ごと読むので、
  「保存」と「取り直し」で2往復ぶん待たされていました。**保存の戻り値に最新の画面を載せ、
  1往復で描く**ようにしています
- **児童画面は起動時にしか読まなかった**：先生が課題や資料を足しても、
  開きっぱなしの端末には出てきませんでした。**30秒ごとに軽い版チェック**をして、
  変わっていたら「先生が学習の内容を新しくしました ▸ 読み込み直す」と本人に促します。
  勝手に描き直すと書きかけのメモや選択中の課題が飛ぶので、押しつけません

スプレッドシートを直接編集した場合（単元シートの取り込みを含む）は、
**開いている教師画面のタブを切り替え直す**と反映されます。

## デモモード（研修・説明会むけ）

ふだんは名簿の `役割` どおりの画面が出ますが、1つのアカウントで
教師画面と児童画面を行き来したいことがあります。

- **教師は、いつでも児童画面を下見できます**（ヘッダーの「児童の画面へ」）。
  設定は要りません
- **児童が教師画面を開けるのは、デモモードのあいだだけ**です。
  メニュー **「自己調整学習アプリ ▸ デモモード：役割の切り替えをオンにする」** で切り替えます

URLに `?as=teacher` / `?as=student` を付けても同じことができます
（切り替えリンクが出ない環境ではこちらを使ってください）。

### 名簿には1行だけ登録します

`役割` を `teacher` にした**1行**で、両方の画面が使えます（デモモードも不要）。
画面の出し分けは名簿を引き直さずに決まるので、**同じメールを2行登録しても切り替えには使えません** ──
`getContext()` は最初に一致した1行を返して止まるため、2行目は無視され、`user_id` の重複で記録が混ざります。

`teacher` の1行で使うと、授業モニタ・みんなの様子・ふりかえり一覧には出ません
（いずれも `役割 === student` で絞っているため）。クラスの集計を汚さずにデモできます。

## この子の画面を見る（読み取り専用）

`?as=student` は「**自分の**児童画面」が出るだけで、特定の児童にはなりません。
ある子の記録がどう見えているかを確かめたいときは、
**授業モニタで児童をえらび、詳細の「👀 この子の画面を見る」**から入ります。

- その子として児童画面が開き、**以降のサーバー関数もその子として動きます**
  （計画・課題の進み方・分かりぐあい・メモ・学びの足跡・学びログが本人の見え方で出ます）
- **書き込みはすべて断ります。** 先生がうっかり触った跡が、その子の学びの足跡に混ざらないようにするためです。
  ただし **デモモードのあいだは書けます**（研修で、児童の操作が教師画面のモニタに映るところまで見せるため）。
  そのときバナーは青くなり「デモ中：操作すると〇〇さんの記録として残ります」と出ます
- 画面上部に「〇〇さんの画面を見ています／読み取り専用」と出ます。
  **「見るのをやめる」**で先生画面に戻ります

見に行けるのは教師（またはデモモード中）だけで、対象は `役割 === student` の人に限られます。
見ている状態は**アクセスしている人のメールを鍵に**保持します
（ウェブアプリは「自分として実行」なので `UserProperties` は全員で共有されてしまい、
1人の設定が全児童に及ぶため使っていません）。

> **デモモードのあいだは教師専用のガードが外れます。** 名簿にいる人なら誰でも
> モニタ・見取りメモ・単元の編集ができてしまいます。**授業で使う前に必ずオフに戻してください。**
> 名簿に載っていない人は、デモモードでも入れません。

## 開発時のテスト（なりすまし）

エディタから動作確認するときは、スクリプトプロパティ `DEV_IMPERSONATE_EMAIL` に
名簿上のメールを設定すると、そのユーザーとしてログインした扱いになります（本番では削除）。

## 研修「単元内自由進度学習」からの設計方針

- **教師は待つ**：モニタは介入を急かす警告ではなく、**環境の診断**（手引き・資料・課題の粒度が足りているか）として表示する
- **見取りは仮説で行う**：見取りメモは事実と解釈（仮説）を分けて記録し、あとで同僚と語り合えるようにする
- **振り返りは反省をしない**：「計画とのズレ」を見て、「こんな教材があれば分かった」を集め、次年度の改善に使う
- **環境は変えないと風景になる**：課題・資料は段階的に公開できる
