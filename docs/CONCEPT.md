# 自己調整学習（SRL）支援アプリ 構想書
## スプレッドシート × Google Apps Script（GAS）による実装構想

---

## 1. コンセプトと基本方針

### 1.1 何を作るか

児童生徒が「**見通す → 実行する（選択・調整） → 振り返る**」という自己調整学習のサイクルを回し、
教師がそれを**設計・見取り・支援**できる Web アプリ。

- **データベース**: Google スプレッドシート（1クラス＝1ファイル）
- **アプリ本体**: GAS ウェブアプリ（`HtmlService` による SPA）
- **配信対象**: Google Workspace for Education のアカウント（教師・児童生徒とも学校アカウントでログイン）

### 1.2 なぜスプレッドシート＋GASか

| 観点 | 利点 |
|---|---|
| 導入コスト | サーバー不要・無料。GIGA端末＋学校のGoogleアカウントだけで動く |
| データの透明性 | 教師がシートを直接開けば全データを見られる。集計・グラフ化も関数で自由 |
| 校務との親和性 | 名簿の取り込み、成績処理へのエクスポートがコピペで済む |
| 保守性 | 教師自身がカスタマイズ可能（方略リストや選択肢はシート上のマスタを書き換えるだけ） |

### 1.3 GASの制約と、それを踏まえた設計判断

| 制約 | 対策 |
|---|---|
| 同時書き込みで行がずれる恐れ | 書き込みは必ず `LockService` で直列化。行の特定はUUIDで行い、行番号に依存しない |
| 実行時間 6分/リクエスト | 1リクエスト＝1操作（目標保存、進度更新など）に細分化。重い集計は夜間トリガーで事前計算 |
| リアルタイムpush不可 | 教師ダッシュボードは **10〜20秒間隔のポーリング**（`google.script.run`）で擬似リアルタイム化 |
| 1日あたりの実行回数クォータ | 授業中の読み書きは差分取得（前回取得時刻以降の更新のみ返す）で呼び出しを軽量化 |
| 児童にシートを直接触らせたくない | ウェブアプリを「**自分（教師）として実行**」でデプロイ。児童はシートへの直接権限を持たず、アプリ経由でのみ読み書き |

## 2. システム全体像

```mermaid
graph TB
    subgraph 児童生徒の端末
        S[児童用画面<br>見通す/実行する/振り返る]
    end
    subgraph 教師の端末
        T1[単元デザイナー]
        T2[授業モニタ<br>ダッシュボード]
        T3[ポートフォリオ閲覧<br>フィードバック]
    end
    subgraph GAS ウェブアプリ
        API[サーバー関数群<br>doGet / google.script.run]
        LOCK[LockService]
        CACHE[CacheService<br>マスタ・差分キャッシュ]
    end
    subgraph スプレッドシート（1クラス1ファイル）
        DB[(データシート群)]
        MASTER[(マスタシート群<br>方略/選択肢/名簿)]
    end
    S --> API
    T1 --> API
    T2 -->|10-20秒ポーリング| API
    T3 --> API
    API --> LOCK --> DB
    API --> CACHE
    API --> MASTER
```

- **1クラス＝1スプレッドシート**を基本単位とする（データ量・権限・パフォーマンスの分離）。
- 学年・学校で共通の「方略マスタ」「選択肢マスタ」はテンプレートファイルからコピーして配布。

## 3. データモデル（シート設計）

### 3.1 マスタ系シート（教師が編集／アプリが参照）

**`名簿` (Users)**
| user_id | 氏名 | 表示名 | 出席番号 | 役割(teacher/student) | 端末アカウント(email) |

**`方略マスタ` (Strategies)** — 調整方略カードの元データ
| strategy_id | 分類(メタ認知/認知/動機づけ/感情調節/援助要請/リソース管理) | カード名 | 児童向け説明(ひらがな可) | アイコン | 推奨フェーズ(見通す/実行/振り返り) |

例: `S-01, 援助要請, 「たすけてカード」, わからないときに ともだちや せんせいに きく, 🙋, 実行`

**`選択肢マスタ` (ChoicePresets)** — 学習の裁量として児童に委ねる選択肢
| preset_id | カテゴリ(場所/順序/ツール/学習形態/課題レベル) | 選択肢ラベル | アイコン |

### 3.2 設計系シート（教師の単元・本時デザイン）

**`単元` (Units)**
| unit_id | 教科 | 学年 | 単元名 | 単元目標 | 総時数 | 状態(準備中/公開/終了) |

**`本時` (Lessons)**
| lesson_id | unit_id | 時数(何時間目) | 本時の目標 | 展開メモ(導入/展開/まとめ) | 裁量レベル(1:指定調整型/2:選択調整型/3:自由調整型) | 状態(下書き/公開中/終了) |

**`課題` (Tasks)**
| task_id | lesson_id | 課題文 | 種別(共通/自由選択) | 評価基準(ゴールの姿) | 添付リンク(Docs/Slides等のURL) |

**`本時_選択肢設定` (LessonChoices)** — 本時ごとに「どの選択肢を児童に開放するか」
| lesson_id | preset_id | 開放する(TRUE/FALSE) |

**`本時_推奨方略` (LessonStrategies)** — 本時に紐づける方略カード
| lesson_id | strategy_id | 教師の一言(この場面で使ってみよう等) |

### 3.3 記録系シート（児童の学習ログ。アプリのみが書き込む）

**`目標` (Goals)** — 見通すフェーズ
| goal_id | lesson_id | user_id | Be(どんな姿で) | Do(何を/成果物) | Regulate(どう工夫するか=選んだ方略ID群) | 作成時刻 |

**`選択` (Selections)** — 実行フェーズの学習方法・環境の選択
| selection_id | lesson_id | user_id | カテゴリ | 選んだ選択肢 | 選択時刻 | 変更前の値(調整の履歴として保持) |

**`進度` (Progress)** — セルフモニタリング
| progress_id | lesson_id | user_id | チェック項目 | 状態(未着手/取組中/完了/困っている) | 更新時刻 |

**`振り返り` (Reflections)**
| reflection_id | lesson_id | user_id | 達成度(スライダー0-100) | 自己評価コメント | 原因帰属(やり方/集中/時間配分/難易度/その他) | 気持ちスタンプ(😊😮‍💨💪😵など) | 次への適用メモ | 記録時刻 |

**`フィードバック` (Feedback)**
| feedback_id | lesson_id | from_user_id(教師) | to_user_id | コメント | 既読フラグ | 送信時刻 |

**`集計キャッシュ` (Summary)** — 夜間トリガーで事前計算
| user_id | よく選ぶ方略TOP3 | 達成度の推移 | 原因帰属の傾向 | 最終更新 |

> 全テーブルの主キーは `Utilities.getUuid()` で発行。**行番号をIDとして使わない**ことで、並べ替え・フィルタ・同時書き込みに対して頑健にする。

## 4. 画面構成

### 4.1 児童生徒用（1画面3タブ。低学年でも迷わない導線）

```
┌─────────────────────────────────────┐
│  きょうの授業: 算数「わり算の筆算」(3/7時間目)   │
│  [① みとおす] [② やってみる] [③ ふりかえる]   │
└─────────────────────────────────────┘
```

**① みとおすタブ**
- 課題とゴール（評価基準）をカードで表示
- 3つの目標入力: **Be**（どんな姿で）／**Do**（何を）／**Regulate**（どう工夫して）
  - Regulate は教師が本時に紐づけた**方略カードからタップ選択**（自由記述も可）
  - Be は定型文チップ（「集中して」「ねばり強く」「協力して」…）＋自由記述

**② やってみるタブ**
- 学習方法の選択カード: 形態（ひとり/ペア/グループ）・場所・順序・ツール
  - 教師が本時で開放した選択肢だけが表示される（裁量レベル1〜3を反映）
- 選んだ方略カードが常時表示され、タップで「つかった！」を記録
- 進度チェックリスト（課題ごとに 未着手→取組中→完了）
- **こまったボタン** 🆘 — 押すと教師ダッシュボードに即表示（援助要請の可視化）

**③ ふりかえるタブ**
- 達成度スライダー（0〜100）＋ゴールとの照らし合わせ
- 原因帰属ガイド: 「うまくいった/むずかしかったのは *なぜ*？」を選択式で誘導（やり方？集中？時間？）
- 気持ちスタンプ＋一言
- 「次はどうする？」（次時・他教科への適用メモ）
- 過去の自分の振り返り履歴をタイムラインで参照（**成長ポートフォリオ**）

### 4.2 教師用

**A. 単元デザイナー**
- 単元の基本情報 → 時数分の本時カードを一覧配置（コマ割り）
- 本時ごとに: 目標・課題・評価基準／開放する選択肢のON/OFF／推奨方略カードの紐づけ
- 「公開」ボタンで児童画面に配信

**B. 授業モニタ（ダッシュボード）** — 授業中のメイン画面
- 座席表/一覧ビューで全員の状態をタイル表示:
  - 立てた目標（Be/Do/Regulate）
  - 選んだ学習形態・場所
  - 進度（色分け: 灰=未着手/青=取組中/緑=完了/**赤=こまっている**）
  - 最終操作からの経過時間（**手が止まっている児童の検知**: 10分無操作で黄色表示）
- タイルをタップ → その子の詳細＋その場でコメント送信
- 10〜20秒間隔のポーリングで自動更新

**C. ポートフォリオ・分析**
- 児童ごと: 達成度推移グラフ、方略選択の傾向、原因帰属の偏り（「いつも集中のせいにしている」等の気づき）
- クラス全体: 振り返り一覧（未記入者の把握）、よく使われた方略ランキング
- 相互参照モード: 教師が「良い目標・工夫」にスターを付けると、児童画面の「みんなの工夫」欄に匿名/記名で共有

### 4.3 AIアシスト（オプション機能）

- 単元目標・課題文を入力すると、**Gemini API**（GAS から `UrlFetchApp` で呼び出し）が
  - 本時の展開案・活動例
  - その場面で有効な調整方略の候補
  を提案し、教師がワンタップで本時デザインに取り込める。
- APIキーは `PropertiesService.getScriptProperties()` に保存。**キー未設定でも全機能が動く**（AIは純粋なオプション）。児童の個人名はプロンプトに含めない。

## 5. GASアプリの構成

### 5.1 プロジェクト構成（clasp でローカル管理 → このリポジトリで版管理）

```
src/
├── appsscript.json          # マニフェスト（timeZone: Asia/Tokyo, webapp設定）
├── Code.gs                  # doGet: ロール判定して児童用/教師用HTMLを出し分け
├── server/
│   ├── Auth.gs              # Session.getActiveUser() と名簿を突合、ロール解決
│   ├── Repo.gs              # シートCRUDの共通層（UUID発行・Lock・型変換）
│   ├── TeacherApi.gs        # 単元/本時/課題の作成・公開、モニタ用差分取得
│   ├── StudentApi.gs        # 目標・選択・進度・振り返りの保存/取得
│   ├── FeedbackApi.gs       # コメント送受信・既読
│   ├── AiAssist.gs          # Gemini呼び出し（オプション）
│   └── Batch.gs             # 夜間集計トリガー（Summaryシート更新）
├── client/
│   ├── student.html         # 児童用SPA（3タブ）
│   ├── teacher.html         # 教師用SPA（デザイナー/モニタ/分析）
│   ├── css.html             # 共通スタイル（インクルード）
│   └── js_common.html       # google.script.run ラッパ、ポーリング制御
└── setup/
    └── Setup.gs             # 初期化: シート群の自動生成、サンプルマスタ投入
```

### 5.2 通信・整合性の要点

- **読み取り**: `CacheService` にマスタ（方略・選択肢・本時設定）を数分キャッシュ。授業モニタは「`updated_at > 前回時刻` の行だけ返す」差分APIでクォータを節約。
- **書き込み**: 全て `LockService.getScriptLock()`（waitLock 10秒）で直列化 → `appendRow` 中心。更新は UUID で行を検索して上書き。
- **doGet 出し分け**: アクセスしたアカウントのメールを名簿と突合し、教師なら `teacher.html`、児童なら `student.html` を返す。名簿にない場合は案内画面。
- **本時の状態遷移**: 下書き → 公開中（児童に見える）→ 終了（振り返りのみ入力可）。教師のワンタップで切替。

### 5.3 セットアップ体験（教師が5分で始められること）

1. テンプレートのスプレッドシートを「コピーを作成」
2. メニューに追加されるカスタムメニュー「SRLアプリ ▸ 初期セットアップ」を実行（シート生成＋サンプルマスタ投入）
3. `名簿` シートにクラス名簿を貼り付け
4. ウェブアプリとしてデプロイ（自分として実行／組織内ユーザーのみアクセス可）
5. 発行されたURLを児童に配布（Classroom 等で共有）

## 6. 開発ロードマップ

| フェーズ | 内容 | ゴール |
|---|---|---|
| **Phase 1: MVP**（まず授業で回す） | Setup／名簿・方略・選択肢マスタ／本時＋課題の公開／児童3タブ（目標Be・Do・Regulate、選択、進度、振り返り）／教師モニタ（一覧＋こまったボタン検知） | 1単元を実際の授業で試せる |
| **Phase 2: 見取りと蓄積** | 座席表ビュー・無操作検知／フィードバック送受信／ポートフォリオ（履歴タイムライン・達成度グラフ）／夜間集計バッチ | 教師の見取り・足場かけと児童のメタ認知支援が機能する |
| **Phase 3: 拡張** | 単元デザイナーの本格UI（コマ割り）／みんなの工夫（相互参照）／Gemini による方略・活動案の提案／複数クラス・他教科展開用のテンプレート化 | 学校単位で展開できる |

### 検討済みの論点（設計判断のメモ）

- **なぜフォーム＋シートでなくWebアプリか**: 「選択→調整→再選択」の往復や進度のリアルタイム把握は、送信一方向のGoogleフォームでは実現できないため。
- **1校1ファイルにしない理由**: 記録系シートは1クラス1単元でも数千行になる。ファイル分割でパフォーマンスと権限管理（担任だけが自クラスを見る）を両立。
- **個人情報**: 児童のメールアドレスと氏名はスプレッドシート内に閉じ、外部API（Gemini）には送らない。
